FEATURES

为「真的能听完」而做的几件事

不只是一个文本转语音的壳子——章节怎么切、歌词怎么对齐、合成中断了怎么办，这些才是听书体验的关键。

📚

多格式输入

epub、txt（自动识别编码）、md / markdown，以及 mobi / azw / azw3（安装可选依赖即可）。

🔖

智能章节识别

内置中英文标题规则：第X章、卷一、Chapter 1、序章、楔子、后记。自动丢弃目录页，也支持自定义正则。

🎵

毫秒级歌词同步

基于 edge-tts 的 WordBoundary 事件逐词生成时间轴，不是按句粗对。音频读到哪一行，字幕就跟到哪一行。

🛡️

工业级韧性

5 次重试 + 指数退避 + 抖动 + 连接节流。遇到 edge-tts 偶发截断，按「预估时长 × 容差」自动检测并重合成。

⏯️

断点续跑

长书跑到一半被打断？--resume 会跳过已完成章节，不重复消耗配额。与 --overwrite 互斥，传错会直接报错。

⏱️

时长预判

--dry-run 在合成前就给出全书预估音频时长；完成后输出「实际 vs 预估」对照，比值过低会告警。

HOW IT WORKS

四步，从一本书到一叠音频

1

读取与清洗

解析 epub / txt / mobi，剔除目录页、页码、脚注残留和装饰行。

reader/ · text_cleaner
2

切分章节

用可配置正则识别标题行，按空行分段，避免把正文切成上百个碎片。

chapter_detector
3

逐段合成

调用 edge-tts 合成 mp3，同时收集 WordBoundary 事件作为歌词时间轴。

edge_tts_client
4

拼接与输出

ffmpeg 拼接片段并插入停顿，写出 lrc、带时间轴的 json 与全书 manifest。

audio · lrc_writer

GET STARTED

安装与快速开始

需要 Python 3.10+ 和系统上的 ffmpeg（用于音频拼接）。

安装

Terminal 
# macOS 安装 ffmpeg（其他平台用对应包管理器）
brew install ffmpeg

# 克隆并安装
git clone https://github.com/mjkki/book2audio.git
cd book2audio
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# 需要 mobi / azw3 支持时
pip install -e .[mobi]

常用命令

Terminal 
# 先看看章节识别对不对（不合成）
book2audio 书.txt --dry-run

# 最简单的转换
book2audio 书.txt --out ./output

# 指定男声 + 稍快语速
book2audio 书.epub --out ./output \
  --voice zh-CN-YunxiNeural --rate +5%

# 中断后续跑，跳过已完成章节
book2audio 书.txt --out ./output --resume

# 章节标题格式特殊时，追加正则
book2audio 书.txt --chapter-pattern "^第.*讲"

常用参数

参数说明
--voice音色，默认 zh-CN-XiaoxiaoNeural（晓晓，女声）；男声常用 zh-CN-YunxiNeural
--rate语速，如 +10% / -10%
--pitch / --volume音调 +10Hz / 音量 +20%
--resume断点续跑，跳过已完成章节（与 --overwrite 互斥）
--overwrite强制重跑所有章节（与 --resume 互斥）
--dry-run只解析章节并预估时长，不合成音频
--chapter-pattern追加章节标题正则，可多次传入
--config加载 yaml 配置文件，命令行参数优先级更高
--gap片段间停顿秒数，默认 0.25

输出文件

文件用途
01-前言.mp3本章节音频
01-前言.lrc同步歌词，播放器会自动加载同名文件
01-前言.json逐句时间轴，方便调试与二次开发
manifest.json全书汇总：章节数、ok / skipped / failed、时长与本次配置
FAQ

常见问题

一本书要跑多久？
edge-tts 大约按 1 倍实时速率返回音频，40 章以上的书通常需要 30 到 60 分钟，大部头可能超过 20 小时。 整章的 mp3 要等该章所有片段拼完才落盘，所以「跑了十分钟没出文件」一般是正常合成中，看日志里有 处理章节 / 完成 → 就说明在推进。
能同时转换好几本书吗？
不建议。同时跑 3 本以上会触发 edge-tts 按 IP 的限流，后启动的章节容易集中出现 ConnectionTimeout。 请一本一本地串行跑，中断后加 --resume 接着来。
章节识别不准怎么办？
先用 --dry-run 预览识别结果，再用 --chapter-pattern 追加你自己的正则。 注意标题行超过 60 字会被丢弃（会打 WARNING 日志提示），遇到「正则写对了却没生效」先看日志。
为什么会有 mp3 只播到一半？
edge-tts 偶尔会返回被截断的音频。项目会按「文字长度预估时长 × 容差」检测这类片段并自动重合成； 如果你手上有旧版本的产物，重跑对应章节覆盖即可。转换结束时输出的「实际 vs 预估」比值低于 0.7 会给出告警。
临时文件会不会占满磁盘？
不会。每章的临时片段目录和 mobi 解包目录在拼接完成后自动回收，并带有「仅限系统临时目录」的护栏。 需要留着片段调试时，可在配置里设 keep_segments: true。
哪些播放器支持歌词？
把整个「书名」目录拷进播放器扫描的文件夹即可。桌面端推荐 foobar2000（需歌词插件）、MusicBee； 手机端推荐海贝音乐、椒盐音乐、网易云音乐本地文件。文件名带章节序号，播放列表顺序就是阅读顺序。
